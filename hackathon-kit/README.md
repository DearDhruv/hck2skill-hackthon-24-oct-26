## ⚡ Self-Enhancing Slash Commands (`/boost`, `/plan`, `/learn`)

Because you are volunteering and busy, you do not need to do manual prompt engineering. The system features three built-in autonomous engines:

### 1. `/boost [instruction]` (Prompt Auto-Expansion Engine)
- **When to use**: Whenever you have a plain-English idea or feature request (e.g. `/boost add search and filter`, `/boost build user dashboard`).
- **What it does**: Activates the **Prompt Auto-Expansion Protocol (PEP)**. It automatically expands your terse input into Clean Architecture (pure Kotlin domain), MVI state contracts (`UiState`, `UiIntent`, `UiEffect`), offline-first mock fixtures, responsive Compose UI, and complete edge cases (empty states, error cards, loading skeletons, text overflow, soft keyboard insets).
- **Result**: Complete, compilable Kotlin files with zero placeholders.

### 2. `/plan [concept]` (4-Hour Hackathon Rapid Execution Planner)
- **When to use**: At the start of the hackathon or when starting a major feature flow.
- **What it does**: Deconstructs the problem against the **1-Flow Rule** and maps tasks across the **4-Hour Time Matrix** (Phase 0 Scope Lock -> Phase 1 Domain & Mock -> Phase 2 Adaptive UI -> Phase 3 Integration & Edge-Case QA -> Phase 4 Submission Freeze).
- **Result**: A structured, hour-by-hour roadmap assigning agent personas and edge-case checkpoints.

### 3. `/learn [lesson]` (Continuous Learning & Instinct Engine)
- **When to use**: Whenever a tricky bug, Kotlin/Wasm quirk, or Compose layout trap is resolved.
- **What it does**: Formulates an atomic instinct (Trigger -> Trap -> Defensive Pattern) and saves it into [Docs/learnings/hackathon_learnings.md](Docs/learnings/hackathon_learnings.md).
- **Result**: Prevents the system from repeating the same mistake for the rest of the sprint.

## 🛡️ Edge-Case Defense Matrix (`INV-EDGE-01`)

Every screen and feature generated by this kit is fortified with out-of-the-box edge-case defenses:

| Edge Case | Failure Risk | Out-of-the-Box Solution |
|---|---|---|
| **Empty State** | Blank screen on 0 results | `EmptyStateCard` with custom icon, explanation, and action button |
| **Error State** | Screen freeze or crash on network drop | `ErrorStateCard` with explicit error badge and "Retry" callback |
| **Loading Latency** | User confusion during delay | `LoadingSkeletonCard` with animated shimmer gradient |
| **Text Overflow** | Long titles break cards | Dynamic labels use `maxLines = 1` or `2` and `TextOverflow.Ellipsis` |
| **Ultrawide Desktop** | Layout stretches across 4K monitors | `AdaptiveContainer(maxContentWidth = 1200.dp)` clamps and centers content (`INSTINCT-002`) |
| **Soft Keyboard (IME)**| Mobile keyboard covers inputs | `AdaptiveFormLayout` with `Modifier.imePadding()` and `verticalScroll` (`INSTINCT-005`) |
| **Form Validation** | Blank or invalid inputs cause crashes | `ValidatedInputField` with character limits, inline errors, and clear button |
| **Double-Click Spam**| Rapid double-tap causes duplicate items | `debouncedClickable(debounceMs = 500)` click protection with ripple preserved (`INSTINCT-008`) |
| **Key Collision** | Timestamp collisions crash LazyColumn | Monotonic counter appended to IDs: `mock_${now()}_${++idCounter}` (`INSTINCT-007`) |
| **Live Stage Outage** | Hotel Wi-Fi drops during live judging | Reactive mock engine with toggle (`isOfflineMode`) and `DemoModeBanner` (`INSTINCT-004`) |
| **Rehearsal Clutter**| Pre-demo test entries pollute state | `resetToSeedData()` restores clean seed state with one tap (`INSTINCT-009`) |
| **Image Load Drop** | Missing avatar or broken URL renders blank | `SafeAsyncImagePlaceholder` fallback container |
| **Wasm Dispatchers** | Single-threaded browser event loop crash | Use `Dispatchers.Default` for CPU work; avoid blocking threads (`INSTINCT-001`) |
| **AI Inference Hang**| On-device LiteRT model takes >4s | `withTimeoutOrNull(4000L)` and `runCatching` with heuristic fallback (`INSTINCT-010`) |
| **Coroutine Teardown**| Swallowing cancellation breaks scope | Ignored `CancellationException` in exception handlers (`INSTINCT-006`) |

## 🚀 Quick Start: 30-Second Initialization

When the hackathon problem statement is announced:

### Scenario A: Inject into a Fresh Repository
Run the bootstrap script targeting your new repository:
```bash
./scripts/bootstrap-new-hackathon-repo.sh /path/to/my-hackathon-app --init-gradle
```
This immediately copies:
- Multi-agent configuration (`.agents/`, `AGENTS.md`, `CLAUDE.md`, `.cursorrules`)
- Clean Architecture Multiplatform scaffolding (Android, iOS, Web Wasm, Desktop)
- Design token system (`SpacingTokens.kt`), Adaptive Navigation (`AdaptiveAppScaffold.kt`), and Responsive Dual-Pane (`AdaptiveTwoPaneLayout.kt`)
- Edge-case UI primitives (`EdgeCaseComponents.kt`)
- Clean MVI StateFlow presentation with crash-safe coroutines (`BaseMviViewModel.kt`)
- Mock-first offline data engine with search & toggle (`MockEngineFixture.kt`) & On-Device AI (`LiteRTQuickEngine.kt`)
- Ready-to-fill Pitch Deck, Architecture docs, Submission forms, and Learnings Registry

### Scenario B: Work Directly in This Workspace
1. Read the problem statement and fill out [Docs/problem_assessment_worksheet.md](Docs/problem_assessment_worksheet.md) (5 minutes).
2. Prompt your assistant:
   > *"/plan [paste problem statement]"*
3. Follow the 4-Hour Timeline below.

## ⏱️ The 4-Hour Hackathon Operating Protocol

Since you are also **volunteering**, your active coding time may be fragmented. Follow this strict, non-negotiable time allocation:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 00:00 - 00:30 │ Phase 0: Problem Scoping & Architecture Lock (Agent 1)      │
│ 00:30 - 01:15 │ Phase 1: Core Domain Models & Mock-First Data Engine        │
│ 01:15 - 02:45 │ Phase 2: Adaptive Compose UI (Mobile, Web, Desktop)         │
│ 02:45 - 03:30 │ Phase 3: Integration (Live API/AI Edge) & QA Invariants     │
│ 03:30 - 04:00 │ Phase 4: Pitch Deck, Demo Video Script & Hack2Skill Freeze   │
└─────────────────────────────────────────────────────────────────────────────┘
```

| Phase | Duration | Objective | Primary Agent | Output Artifacts |
|---|---|---|---|---|
| **Phase 0: Scope & Architecture** | 30 min | Deconstruct problem into 1 core workflow; formulate domain models | `architect-scaffolder` | Domain entities, use cases, screen wireframes |
| **Phase 1: Domain & Mock Data** | 45 min | Implement domain layer + reactive mock repository with realistic delay | `engine-data-integrator` | StateFlow repos, seed data fixtures, zero network dependencies |
| **Phase 2: Adaptive Compose UI** | 90 min | Build UI using Material 3 Adaptive, NavigationSuite, and Spacing tokens | `cmp-ui-designer` | Mobile bottom bar, Tablet rail, Desktop/Web drawer, cards |
| **Phase 3: Integration & QA** | 45 min | Wire live API/LiteRT AI, verify dark/light mode, edge cases, rotation | `quality-verifier` | Production polish, zero crash paths, smooth animations |
| **Phase 4: Submission Lock** | 30 min | Finalize README, Mermaid architecture diagrams, pitch deck, video script | `pitch-submission-lead` | Hack2Skill submission text, pitch slides, GitHub release |

## 🏛️ Clean Architecture & Multi-Device Parity

```
                       ┌─────────────────────────┐
                       │   UI Layer (Compose MP) │
                       │  Mobile / Web / Desktop │
                       └────────────┬────────────┘
                                    │ observes UIState
                                    ▼
                       ┌─────────────────────────┐
                       │ Presentation Layer (MVI)│
                       │ StateFlow / ViewModels  │
                       └────────────┬────────────┘
                                    │ calls UseCases
                                    ▼
                       ┌─────────────────────────┐
                       │  Domain Layer (Pure KMP)│ ◄── Zero Android/UI deps
                       │  Entities / UseCases    │
                       └────────────▲────────────┘
                                    │ implements interfaces
                                    │
                       ┌────────────┴────────────┐
                       │ Data Layer (Offline 1st)│
                       │ Mock Engine / Ktor / DB │
                       └─────────────────────────┘
```

### Supported Devices & Adaptive Navigation
- **Compact (Mobile Phones < 600dp)**: Bottom Navigation Bar via `NavigationSuiteScaffold`, single-column vertical feed, capsule buttons.
- **Medium (Tablets & Foldables 600–840dp)**: Navigation Rail on screen edge, dual-pane `AdaptiveTwoPaneLayout`.
- **Expanded (Desktop & Web Wasm > 840dp)**: Modal/Permanent Navigation Drawer, multi-column grid layouts, clamped max-width container (`AdaptiveContainer`), mouse hover states.
